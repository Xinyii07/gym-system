# SJY Fitness - Gym Service Management System

A C++ console application for managing a gym: member accounts, class/personal-trainer bookings, lockers, billing, and BMI/diet/workout recommendations. Built as a group assignment.

## Project structure

```
gym-system/
  CMakeLists.txt      Build configuration (builds everything in src/, headers from include/)
  include/            Header files (one per module, plus shared Config/Types/UIUtils)
  src/                Implementation files
  build/              Generated by CMake - not committed
  data/               Generated at runtime (save files) - not committed
```

### Modules (`include/` + `src/`)

| Module | Responsibility |
|---|---|
| `Config.h` | App-wide constants (limits, day/slot names, tax rate) |
| `Types.h` | Shared data structs: `Member`, `Master`, `GymService`, `Booking`, `LockerDevice`, `Payment` |
| `UIUtils` | Console rendering helpers (boxed layout, headers, pause, masked password input, arrow-key list picker) and small utilities (date, email/phone validation) |
| `DataStore` | Loads/saves every data type to `data/*.dat` so state survives a restart |
| `MemberModule` | Registration, login, profile editing, master directory, membership renewal |
| `ServiceBookingModule` | Class schedules, creating/editing/canceling bookings, admin service & appointment management |
| `LockerModule` | Locker rental/release, admin locker reset |
| `BillingModule` | Charges, pending payments, payment history, invoices, confirming payments |
| `RecommendationModule` | BMI calculator, diet plan, workout plan |
| `ReportsModule`, `LoyaltyModule` | Placeholder menus - not yet implemented |
| `main.cpp` | Entry point: owns all in-memory data arrays and the login/dashboard menu loops |

## Building

Requires a C++17 compiler and CMake. On Windows with Visual Studio installed:

```powershell
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Debug
```

(Adjust the generator name to whatever Visual Studio version you have, or drop `-G`/`-A` to let CMake pick a default. On other platforms/toolchains, `cmake -S . -B build && cmake --build build` works the same way.)

Alternatively, open the folder directly in Visual Studio (File → Open → Folder...) — it auto-detects `CMakeLists.txt` and gives you a normal Run/Debug (F5) button.

## Running

```powershell
build\Debug\gym_system.exe
```

It's a console app that reads from stdin, so run it from a real terminal window.

### Login

| Role | Username | Password |
|---|---|---|
| Admin | `admin` | `admin123` |
| Member | `M1001`–`M1004` | `123` |

New members are registered from Member Management → All Members List → Add Member (available to any logged-in user, not just admin); a member ID is assigned automatically. The same screen also lets you Remove or Edit a member, picking them from an arrow-key list (Up/Down to move, Enter to select, Esc to cancel) instead of typing an ID.

Passwords (login, registration, password change) are masked as you type.

### Data persistence

On first run, the app seeds itself with demo data (4 members, 2 masters, 4 services, 8 lockers) and writes it to `data/`. From then on, every add/edit/cancel/booking/payment action is saved to `data/*.dat` immediately, so the program remembers its state the next time it's launched. Delete the `data/` folder to reset back to the demo seed data.
